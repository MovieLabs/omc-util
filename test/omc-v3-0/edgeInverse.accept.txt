# Findings edgeInverse.js should not fail on for the SHIPPED table.
#
# The subject is the union of the publication and the edges.js seed, which is what
# omcTemplate.inverseEdge() answers from and therefore what fMam writes reverse edges from.
#
# Three groups, none of them a fault in the data:
#   INVERSE-MALFORMED / INVERSE-UNDECLARED around hasCxt, cxtFor and `has` come from the seed, and
#     go when the publication covers Context and the seed is dropped.
#   INVERSE-BUCKET and INVERSE-OVERRIDE are structural: inverseEdge() returns a bare name, so it
#     can express neither an intrinsic inverse nor a per-group one. Closing them needs an accessor
#     that returns the inverse edge rather than its name.
#   NOT-INVOLUTIVE is a modelling question about the uses/usedBy/usedIn and realizedBy triangles.
