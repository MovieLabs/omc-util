# --- INVERSE-MALFORMED ------------------------------------------------------------------------
#
# `has` group 6 gives its inverse as "realizationProperties.RealizationBy" — a storage path where a
# predicate name belongs. resolveInversePath cannot find a predicate by that name, so it falls back
# to the edges default and builds a four-segment path that is not a place an edge can live. The
# predicate is `RealizationBy`, and it declares no `path`, which is presumably why the path was
# written into the inverse instead. Fixing it means naming the predicate and giving that predicate
# its schema path.
INVERSE-MALFORMED has on Composition: the group names inverse "realizationProperties.RealizationBy", which is not a predicate, so the table resolved "edges.realizationProperties.RealizationBy.Composition"
INVERSE-MALFORMED has on Participant: the group names inverse "realizationProperties.RealizationBy", which is not a predicate, so the table resolved "edges.realizationProperties.RealizationBy.Participant"

# --- NOT-INVOLUTIVE ---------------------------------------------------------------------------
#
# uses / usedBy / usedIn are three predicates where the other pairs are two, so the round trip does
# not return. Which pairing is intended is a modelling question.
NOT-INVOLUTIVE usedBy -> usedIn -> uses

# --- INVERSE-BUCKET ---------------------------------------------------------------------------
#
# memberOf and productOf invert onto intrinsic properties (Member, Product). buildEdgeTable knows
# that and resolves inversePath to the property; omcTemplate.inverseEdge returns only the name, so
# fMam writes edges.Member.<Type> instead. Closing this needs an accessor that returns the inverse
# edge rather than its name — an omcUtil change, not a definitions change.
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes "edges.Member.Asset"
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes "edges.Member.Infrastructure"
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes "edges.Member.Participant"
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes "edges.Member.Task"
INVERSE-BUCKET productOf -> Product — intrinsic property, table path "Product", fMam writes "edges.Product.Asset"
