# Findings edgeInverse.js should not fail on.
#
# One line per finding, copied verbatim from the report. Blank lines and `#` comments are ignored.
# An entry is a claim that the finding is known — say why beside it, and remove it when the gap
# closes.
#
# This is the state edges.js was in when the check was written. Three root causes account for all
# of it.

# --- NOT-INVOLUTIVE -------------------------------------------------------------------------
#
# uses / usedBy / usedIn are three predicates where the other pairs are two: usedBy's inverse is
# usedIn, but usedIn's inverse is uses, so the round trip does not return. Which of the three
# pairings is intended is a modelling question.
NOT-INVOLUTIVE usedBy -> usedIn -> uses

# --- INVERSE-BUCKET -------------------------------------------------------------------------
#
# memberOf and productOf invert onto intrinsic properties (Member, Product). The edge table knows
# that and resolves inversePath to the bare property, but omcTemplate.inverseEdge() returns only
# the name, so fMam writes edges.Member.<Type> instead. Closing this needs an accessor that
# returns the inverse edge rather than its name — an omcUtil change, not a definitions change.
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes edges.Member.Asset
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes edges.Member.Infrastructure
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes edges.Member.Participant
INVERSE-BUCKET memberOf -> Member — intrinsic property, table path "Member", fMam writes edges.Member.Task
INVERSE-BUCKET productOf -> Product — intrinsic property, table path "Product", fMam writes edges.Product.Asset
