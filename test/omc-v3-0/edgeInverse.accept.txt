# Findings edgeInverse.js should not fail on for the SHIPPED table.
#
# The subject is the union of the publication and the edges.js seed, which is what
# omcTemplate.inverseEdge() answers from and therefore what fMam writes reverse edges from.
#
# INVERSE-BUCKET and INVERSE-OVERRIDE are structural, not data faults: inverseEdge() returns a bare
# predicate name, so it can express neither an intrinsic inverse nor a per-group one, and fMam then
# writes to a place the table does not agree with. Closing them needs an accessor that returns the
# inverse edge rather than its name.
#
# INVERSE-MALFORMED and most INVERSE-UNDECLARED come from the seed - the Context carrier, and the
# `has` group whose inverse names a path rather than a predicate - and go when the publication
# covers Context and the seed can be dropped.
#
# NOT-INVOLUTIVE is a modelling question about the uses/usedBy/usedIn and realizedBy triangles.
